# Сетевые наказания, проверка при входе и чат (форк koiie111)

Документ описывает, как плагин применяет наказания на сети серверов с общей БД, и что именно он гарантирует.
Версии платформы: .NET 10, CounterStrikeSharp.API 1.0.369 (`MinimumApiVersion(369)`).

## 1. Область действия: наказания сетевые, права — нет

* **BAN, GAG, MUTE, SILENCE и WARN действуют на всех серверах с общей БД.** Ни один запрос наказаний не фильтрует по
  `server_id`: ни чтение, ни снятие (`css_unban/ungag/unmute/unsilence/unwarn`), ни истечение, ни кеш банов, ни подсчёт
  счётчиков/истории/предупреждений, ни онлайн-время (TimeMode 0).
* `server_id` по-прежнему **записывается** в строку — как сведение о том, где наказание выдано. Столбцы не удалены, схема и
  SQL-миграции не менялись. `NULL`, `0` и «устаревший» id другого сервера не влияют на решение.
* **`MultiServerMode` больше не влияет на наказания.** Параметр оставлен, чтобы старые конфиги загружались; значение `false`
  ведёт себя как `true`. Права администраторов, группы и серверные настройки (`sa_admins.server_id`,
  `sa_groups_servers`) остаются серверными — это другая область действия.
* Источник выдачи не важен: другой сервер, сайт, онлайн/офлайн-команда, API.
* Истёкшие и снятые наказания не действуют. Постоянное наказание (`duration = 0`) не истекает из-за `ends`
  (в БД `ends` у него фиктивный = время выдачи): в SQL и в памяти длительность 0 проверяется раньше `ends`.
* TimeMode: `1` — до `ends` по реальному времени; `0` — по минутам онлайна (`passed`, `NULL` = 0). Начисление минут идёт
  идемпотентно (compare-and-set), одна запись начисляется один раз; отметка «минуты исчерпаны» ставится на конкретную
  строку по `id`, а не по совпадению времени окончания.

## 2. Вход игрока: решение принимает общая БД

1. `OnClientAuthorized` (void в CounterStrikeSharp 1.0.369) и `player_connect_full` создают **одну сессию подключения**
   (slot + userid + SteamID64) и ставят загрузку в очередь БД. SteamID = 0 (авторизация не закончена) проверкой не считается:
   загрузка не стартует, пока SteamID не подтверждён.
2. Бан по подтверждённому SteamID64 читается **из БД параметризованным запросом по SteamID** на каждое подключение
   (`status = 'ACTIVE'` и `duration <= 0 OR ends IS NULL OR ends > now`; граница `ends == now` — бан закончился, как в SQL-джобе
   истечения). Результат не зависит от `BanType`, IP, `IgnoredIps`, `CheckMultiAccountsByIp`, `server_id` и от свежести
   локального кеша. Бан, выданный на другом сервере за секунду до входа, находится; бан, снятый секунду назад, не блокирует.
3. Проверки по IP (`BanType > 0`, общий IP, связанные аккаунты) только **дополняют**: кеш предлагает кандидата, БД
   подтверждает, что именно эта строка бана ещё активна. Устаревшая положительная запись кеша не создаёт ложный бан.
4. Активные GAG/MUTE/SILENCE читаются из БД в той же загрузке и применяются до любых второстепенных операций.
5. **Что гарантируется по времени.** `OnClientAuthorized` не умеет отклонять рукопожатие, поэтому это **не синхронный
   pre-auth reject**: игрок отключается (`Disconnect`) сразу, как приходит ответ БД, то есть через время одного запроса
   после авторизации (обычно миллисекунды, при медленной БД — до её таймаута). Отключение не зависит от `KickTime`,
   пешки, оружия, эффектов и от вспомогательного `banid`/`UnlockConCommands`.
6. Запись IP (`sa_players_ips`, нужна сайту) выполняется отдельным заданием: её задержка или ошибка не откладывают
   решение и отключение. Статистика (счётчики, уведомление админам) загружается после применения ограничений; её ошибка
   оставляет счётчики нулевыми и никак не влияет на наказания (контракт b43a6b7/fbabb7a пересмотрен именно так).

### Сбой проверки

Ошибка БД, таймаут, переполнение очереди, плагин не в состоянии `Ready`, неготовый кеш — **не** «наказаний нет». Такое
подключение остаётся непроверенным, загрузка повторяется с задержкой (2, 5, 15, 30, затем 60 с).
`OtherSettings.UnverifiedConnectionTimeoutSeconds` (по умолчанию **45**, допустимо 10–600) ограничивает ожидание: по
истечении срока сессия, не дошедшая до состояния *Loaded*, отключается (`NETWORK_DISCONNECT_REJECT_INVALIDCONNECTION`),
в лог пишется диагноз (состояние загрузки, число попыток, состояние плагина, последняя ошибка). Игроку при этом **не
записывается** ни бан, ни другое наказание. Уже проверенные игроки при падении БД не отключаются; последний известный набор
ограничений сохраняется.

## 3. Онлайн-игроки: синхронизация

Раз в проход обслуживания (61 с) для каждого загруженного онлайн-игрока ставится задание чтения его активных записей
**в его персональную упорядоченную очередь** (`Runtime.TryQueueDbOrdered`, ключ — SteamID64), то есть после всех ранее
принятых mute/unmute/connect-load этого игрока и до всех последующих. Ответ применяется на игровом потоке, только если
сессия всё ещё текущая (slot + userid + SteamID).

* Новая запись добавляется; изменённая (продление, замена на более долгую/постоянную) заменяет прежнюю; запись, которой нет
  в ответе (снята/истекла на другом сервере), удаляется; несколько перекрывающихся записей и типов поддерживаются
  (в памяти запись несёт `sa_mutes.id`).
* Записи, принятые **после** чтения (команда на этом сервере), устаревшим ответом не удаляются; снятый мут устаревшим ответом
  не воскрешается (порядок очереди гарантирует, что чтение раньше unmute применилось раньше него).
* Успешный пустой ответ снимает записи; ошибка чтения не меняет ничего (исключение, а не «пусто»).
* `VoiceFlags.Muted` ставится/снимается только этим битом; голос освобождается лишь когда не осталось ни MUTE, ни SILENCE.
* Предел задержки: новое/изменённое/снятое наказание достигает онлайн-игрока этого сервера **не позже следующего прохода
  (≈ 61 с) плюс время очереди БД**. Бан онлайн-игрока: кеш обновляется в том же проходе, положительный результат
  подтверждается БД перед `Disconnect` (≤ ≈ 61 с). Redis для этого не используется и не нужен; `RedisInform` остаётся
  только уведомлением.
* Один запрос на игрока (в своей очереди) вместо общего пакета — осознанная цена порядка операций; пакетное чтение
  (`GetActiveMutesBatchAsync`) используется там, где порядок не нужен.

## 4. Отключение (`Helper.KickPlayer`)

Обе перегрузки идут через `KickFlow`: **обязателен только `Disconnect`**. Заморозка/окраска/блокировка оружия — украшение;
отсутствие пешки, мёртвый или наблюдающий игрок, `WeaponServices == null`, исключение в эффекте или в `banid` его не
отменяют. Немедленный кик не подавляется ранее выставленным `WaitingForKick`. Отложенный кик не держит контроллер: таймер
заново находит слот и отключает только то же подключение (slot + userid + SteamID64), поэтому переиспользованный слот
не затрагивается.

## 5. Чат для GAG/SILENCE

Глобальный слушатель команд (`AddCommandListener(null, …)`) выполняется до обработчика чата движка. В CounterStrikeSharp 1.0.369
строка `!cmd` печатается движком в `Host_Say` (если не «тихий» `/`), а затем отдельно диспетчеризуется как `css_cmd`;
`HookResult.Stop` из слушателя на `say` отменяет **и то, и другое**. Поэтому для игрока с GAG/SILENCE:

* `say`/`say_team` с обычным текстом, `@…`, с пробелами/кавычками перед триггером — блокируются (с уведомлением).
* Строка с триггером (`!текст`, `!hello`, `!hello world`, `/текст`, `!!x`, `! x`, неизвестная команда, цепочки через `;`,
  кавычки, управляющие символы, длинная строка) — блокируется без каких-либо действий.
* Команды рассылки плагина и любые команды с `say` в имени (`css_say`, `css_psay`, `css_csay`, `css_hsay`, `css_cssay`,
  `css_asay`, `sm_say` …), набранные в консоли или через триггер, — блокируются. Проверка по подстроке `say` сохранена для
  всех команд; точное сравнение используется только чтобы отличить настоящие `say`/`say_team`.
* Единственное исключение: команда из **allow-list**, которая только отвечает вызвавшему. Это собственные команды плагина,
  кроме перечисленных выше (учитываются алиасы из `Commands.json`), и имена из
  `OtherSettings.GagAllowedChatCommands` (без триггера и без `css_`, по умолчанию пусто). Она выполняется ровно один раз
  через `ExecuteClientCommandFromServer("css_имя аргументы")` с обычной проверкой прав и аргументов; аргументы — печатный
  ASCII без `;`, `"` и `\`, не длиннее 128 символов. Команды других плагинов, зарегистрированные через API, и неизвестные
  команды — не разрешены, пока явно не добавлены в список. Имена со `say` разрешить нельзя.
* Игрок только с MUTE пишет как обычно (MUTE ограничивает голос, GAG — текст, SILENCE — оба канала).
* `UserMessageGagChatType = true` включает вторую линию: пользовательские сообщения SayText2 (118) автора с GAG/SILENCE
  отбрасываются независимо от локализатора и даты окончания.

**Границы совместимости.** Плагин не может отфильтровать любой `PrintToChat` стороннего плагина: перехватываются слушатель
команды `say*` и сообщение 118. Если сторонний chat processor зарегистрирован раньше этого плагина, его слушатель выполняется
раньше (слушатели вызываются в порядке регистрации) и уже мог разослать текст; если позже — видит остановленную команду.
Плагин, который сам формирует вывод без SayText2 с индексом автора (или с другим автором), для хука 118 невидим. Рекомендуется
загружать SimpleAdmin раньше chat processor'ов и проверять на стенде (см. §7).

## 6. Настройки

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `OtherSettings.UnverifiedConnectionTimeoutSeconds` | 45 | Срок непроверенного подключения (10–600 с). |
| `OtherSettings.GagAllowedChatCommands` | `[]` | Команды, доступные игроку с GAG/SILENCE через триггер. |
| `MultiServerMode` | `true` | Устарел и игнорируется для наказаний. |

## 7. Проверки

`dotnet test tests/CS2-SimpleAdmin.Tests` — поведенческие тесты на реальных БД (SQLite; MySQL 5.7/8.0, MariaDB 10.11 при
`SA_TEST_MYSQL`/доступных портах, `SA_REQUIRE_MYSQL=1` делает недоступный сервер ошибкой): сеть серверов при обоих
значениях `MultiServerMode` и любых `server_id`, SteamID-бан при любых `BanType`/IP/`IgnoredIps`, границы `ends`,
вставка бана после последнего обновления кеша и обратный случай, отказ чтения ≠ «пусто», срок проверки, независимость
стратегии от IP/статистики, синхронизация (добавить/продлить/второй тип/снять/перекрытие/ошибка/чужой слот),
`KickFlow`, решения чата.

**Не проверялось без стенда CS2:** реальные `Disconnect`/`VoiceFlags`/чат на двух серверах с общей БД, получение
сообщений вторым клиентом, совместимость с установленным chat processor. Эти проверки остаются за владельцем сервера.
